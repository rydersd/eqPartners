Design Notes

Summary

Step 4 (final) of the Deal Registration wizard. Jordan Reeves reviews a read-only summary of all information entered across the prior three steps. Each section is collapsible and has an inline Edit link that returns to the relevant step. A legal terms acceptance checkbox is required before submission. The Submit button is visually distinct (green) to signal finality.

Flow Position

  • Previous: pc-dr-step3.html (Sales Contact)
  • Next: Deal registration confirmation / Registered Deals list (pm-deal-registration.html)

Design Decisions

  • Accordion sections — Each step's data shown as a collapsible block. All open by default so the full summary is immediately visible on arrival. User can collapse to reduce scroll if needed.
  • Inline Edit links — Each section header has an "Edit" link back to the relevant step, making correction frictionless without having to navigate the stepper manually.
  • Legal checkbox — Required before Submit is active (validation on submit). Separate from the form data sections so it's visually distinct as a consent action.
  • Green Submit button — Color-differentiated from the blue "Next" buttons on prior steps to signal this is the terminal action. Label reads "Submit Registration" not "Next."
  • Sample data — Review sections are pre-populated with realistic CloudBridge / Acme Corporation scenario data to make the wireframe legible as a design artifact.
  • AI rail — Will surface pre-submission checks (duplicates, completeness, approval likelihood) in a future release.

Post-Submit State

  • On success: redirect to a confirmation screen (not yet wired) → then to pm-deal-registration.html (Registered Deals list)
  • On duplicate detected: show inline warning, allow user to proceed or cancel
  • On server error: show error banner, preserve form data, allow retry
