Design Specs

Summary

Single unified table of all 44 partner training courses with Business / Technical type filtering, status filtering, keyword search, and 25-row pagination. Steve Rogers (CloudBridge Inc.) view — 4 of 13 required courses completed, 1 expired (Security Fundamentals). Enroll and resume actions handled in SumTotal LMS; not surfaced in this portal view.

Open Questions for Discussion

  • Filter dimensions: Business / Technical is the proposed primary filter — does this match how partners think about the catalog? Or do they navigate by Category (Compliance, Networking, Sales) instead?
  • Required vs. Elective: Currently surfaced as a mini-tag in the Name column and as a Status filter option. Should it be a standalone filter pill alongside Business / Technical?
  • Column set: Start Date is low-value for most users — candidate to drop and recover width for Name / Category. Should % Complete and Score live here or only on a row-expand / course detail page?
  • Expiry urgency: Expired rows are tinted light red. Should rows expiring within 30 days get a warning state (amber) before they go red?
  • Enroll CTA: Currently omitted — all enrollment goes to SumTotal. Should the portal surface a "Launch in SumTotal" link at row level, or is a single "Go to SumTotal" button in the header enough?
  • Page size: 25 rows default. Should users be able to switch to 10 / 50 / All?

What Changed

  • Replaced 4 separate tab-tables (each with its own <thead>) with a single table — one fixed header, columns never shift
  • table-layout: fixed with explicit column widths prevents cell content from pushing columns out of alignment
  • Actions column removed — enroll / resume / download handled in SumTotal LMS
  • Type filter (Business / Technical) added as discussion prompt; counts update dynamically as other filters narrow the set
  • Pagination at 25 rows per page
  • Dates use Salesforce format: M/D/YYYY

Technical Notes

  • All filtering and pagination is client-side JS over a static data array — no SOQL on this prototype
  • Production: filter state should persist in URL query params for back-button and deep-link support
  • Required / Elective distinction stored as req field; Status dropdown maps "Required only" and "Elective only" to this field
  • Expired row highlighting via .row-expired class applied in JS at render time
