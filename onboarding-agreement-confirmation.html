Design Specs

Summary

Minimal transactional confirmation page shown immediately after the user signs the Partner Program Agreement. The user is not authenticated at this point — no portal chrome, no navigation. Shows two email previews: one confirmation sent immediately, one preview of the account-ready email with a one-time login link that arrives once Equinix countersigns.

Flow context

  • Previous step: User signs agreement on onboarding-agreement.html (DocuSign redirect back)
  • This page: Unauthenticated transactional receipt — user is not yet in the portal
  • Email 1: Sent immediately on agreement receipt — confirms status, sets expectation
  • Email 2 (preview): Sent ~1–2 business days later when account is provisioned — contains one-time login link to create initial session
  • Next step for user: Click login link in Email 2 → partner-login.html or direct portal entry

Design Decisions

  • No wf-header nav — user is unauthenticated; portal chrome would be misleading
  • No progress stepper — this is a terminal state in the pre-auth flow; the stepper resumes inside the portal after first login
  • No "While You Wait" portal actions — user cannot access portal resources yet
  • Two-email sequence diagram communicates the full handoff without implying the user can do anything right now
  • One-time login link pattern: JWT token in URL, 72-hour expiry, single-use — avoids password creation friction, common in B2B SaaS onboarding

Technical Details

  • Email 1 trigger: Fired by Salesforce Process Builder when Partner_Agreement__c.Status__c transitions to 'Partner Signed'
  • Email 2 trigger: Fired when Partner_Agreement__c.Countersign_Status__c = 'Fully Executed' and Partner_Central_User__c.Account_Status__c = 'Provisioned'
  • Login token: Short-lived JWT stored in Auth_Token__c on the Partner_Central_User__c record; single-use flag set on redemption; 72-hour TTL enforced server-side
  • Post-login destination: onboarding-welcome.html (first-time flag detected from User__c.First_Login__c = null)
