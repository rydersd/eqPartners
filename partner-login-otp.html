Design Specs

Summary

Passwordless login for users who set up "Email code" as their auth method during onboarding. Replaces partner-login.html password form for this user segment. Two-step: email entry → 6-digit OTP → authenticated session.

Flow Position

This screen handles ongoing logins only. It is not the first-login experience. New users arrive via the magic link in the welcome email → onboarding-auth-setup.html (where they choose SSO, TOTP, or Email code as their method). This screen is what Email-code users see on every subsequent login.

Comparison: Three Auth Paths

  • SSO: user enters email → redirected to IdP (Google/Okta/Microsoft) → authenticated. No code, no password.
  • TOTP: user enters email → enters 6-digit code from their authenticator app. Code is generated locally, not sent.
  • Email code (this screen): user enters email → system sends a 6-digit OTP to that inbox → user enters it here. Works on any device with email access. No app required.

States

  • Email entry: Single email field + "Send me a code" CTA. SSO option shown below for SSO-eligible domains.
  • Code entry: Blue delivery banner confirms which address received the code. 6 OTP boxes + paste-capable hidden input. Countdown timer (10 min). Resend link becomes active after 60 seconds.
  • Error — unknown email: Red banner inline on email step. Link to apply.
  • Error — bad code: Red banner inline on code step with "Send a new code" shortcut.

Technical Details

  • OTP generation: 6-digit numeric code, cryptographically random (CSPRNG). Stored hashed (bcrypt) against user record. Single use.
  • TTL: 10 minutes from issue. Expired codes return the same "incorrect or expired" error as wrong codes — no timing difference exposed.
  • Email delivery: Marketing Cloud transactional send (same template as PCP-CONFIRM family). Subject: "Your Partner Central login code: 472 XXX".
  • Rate limit: Max 5 sends per user per hour. After 5: show "Too many attempts — try again in 1 hour" and suppress the send button.
  • Resend timer: 60-second cooldown before resend is enabled, to reduce duplicate sends. Timer shown in the UI.
  • SSO domain detection: On blur of email field, check domain against SSO_Domain__c. If match, suggest SSO as primary path.
  • One-time code input: Production uses a single hidden <input type="text" inputmode="numeric" autocomplete="one-time-code"> — browser autofill from SMS/email will populate this. The styled digit boxes are a visual overlay.
  • On success: POST /auth/verify-otp → session cookie issued → redirect to pm-home-dashboard.html (or rep-home.html based on role).

Accessibility

  • Email field: autocomplete="email", labeled
  • OTP input: autocomplete="one-time-code" supports iOS/Android SMS autofill
  • Delivery banner: role="status" aria-live="polite"
  • Error banners: role="alert" — announced immediately to screen readers
  • Timer: aria-live="polite" so it doesn't interrupt but updates are heard
