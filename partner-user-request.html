About This Page

Two-perspective wireframe covering the full subsequent user (rep/admin) registration flow. Toggle between the new user's join request flow and the org admin's approval view. In production these are two separate UX contexts: pre-auth (new user) and post-auth admin settings (Portal Admin).

Email-exists check gate (Step 1)

Before reaching the org search, the user enters their work email. The system checks whether that email already has an account in Experience Cloud. If yes → redirect to login. If no → proceed to org search. This prevents duplicate account creation and handles the common case where a rep has already been set up by an admin without their knowledge.

Experience Cloud supports this via a REST query against the Contact/User object. The gate should be a lightweight async check — not a full page load. Show a spinner while checking.

Design rationale: org admin, not PSM

The current system routes new user setup through the PSM team, which creates a bottleneck and conflates program management with routine user admin. Org admins are better positioned — they know their own employees, can act without Equinix involvement, and are accountable for their team's portal usage.

PSM as fallback (if no admin is assigned) preserves the existing behavior for the transition period and covers edge cases like single-person partner orgs.

Self-registration industry norm

B2B partner portals from Cisco, Palo Alto Networks, and AWS all allow reps to self-register with org admin approval. PSM-gated user creation is an outlier pattern. Removing it reduces PSM overhead and improves rep time-to-first-deal.

Email domain matching

Suggest validating the requester's email domain against the registered org domain (cloudbridge.com) before allowing submission. Show a soft warning — not a hard block — to account for contractors and partners using different domains.

Role assignment at approval time

The admin selects the actual role at approval time, overriding the role the requester asked for. This keeps the admin in control of access levels and avoids automatic escalation to higher-privilege roles.

Personas

Requester: Alex Kim (new CloudBridge hire, needs deal registration access). Approver: Jordan Reeves (Portal Admin). Alex is not a named persona in the main cast — introduced here as a supporting character for this flow.

Full flow (subsequent user path)

Email check (this page) → Org search (this page) → Submit join request (this page) → Admin approves/denies (this page, admin view) → Rep approval email (onboarding-rep-approval-email.html) → OTP login + auth setup (onboarding-auth-setup.html) → Orientation or first-time login (rep-first-login.html).

Admin approval triggers a distinct email from the org application approval email (PCP-APPROVE). The rep approval email links directly to an OTP verification screen, not a password-creation screen — Experience Cloud passwordless email OTP is available out of the box since Winter '23.
