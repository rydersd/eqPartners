✦ Einstein Document Generation — Implementation Spec

The Generate with Einstein button triggers Salesforce Einstein Document Generation (generally available as of Summer '24 in Salesforce Enterprise and Unlimited editions). This spec covers the full implementation: data model, prompt template, API flow, and output behavior.

Why Einstein DocGen for Escalation Briefs?

Unlike static merged documents (Salesforce Document Builder, Conga), Einstein DocGen uses a generative prompt to synthesize structured CRM data into coherent narrative — ideal for executive-facing content where tone, emphasis, and recommended talking points require judgment, not just field values. The brief content shown above (sections 1–4) is entirely AI-generated from CRM data; PSM reviews and edits before sending.

Salesforce Configuration Steps

  1. Enable Einstein Document Generation in Setup → Einstein → Document Generation (requires Einstein 1 or Salesforce Enterprise + AI add-on)
  2. Create Prompt Template: Setup → Einstein → Prompt Templates → New → Type: Document Generation → Object: Escalation__c
  3. Paste prompt template above; add merge fields using the field picker. Add related object fields via the dot-notation picker (Escalation__c.Account__r.Name)
  4. Associate a Document Template (PDF layout with Equinix letterhead) — use the Document Template builder or upload a DOCX template. The generated text is injected into a designated placeholder region
  5. Add the Generate Document quick action to the Escalation__c page layout. This renders the "Generate with Einstein" button on this screen
  6. Configure output: PDF delivery. Set Post-Generation Action to: (a) attach PDF to the Escalation record as a File, (b) log a completed Task on the partner Account, (c) optionally trigger a Flow to email the PDF to the VP_Reviewer__c contact
  7. PSM sees a preview modal before download/send — they can edit the generated text inline before finalizing

Permissions and Governance

  • Generation is available to PSM and PAM profiles only (not AE or partner portal users)
  • Each generation is logged with timestamp, user, and model version for audit purposes
  • The generated PDF is versioned — regeneration creates a new version, previous drafts are retained
  • VP recipient receives the PDF via Salesforce Email (template: Equinix branded, sends from PSM's email alias)

Einstein Model Details

Einstein DocGen uses the configured Einstein generative model within the org — defaults to the Salesforce-hosted model (based on Azure OpenAI) or can be pointed to a Bring Your Own Model (BYOM) connector. No data leaves Salesforce's trust boundary. Prompt + CRM data are processed within the Salesforce Einstein AI layer; no external API call to OpenAI is made in the standard configuration.
