Design Specs

Summary

First-time account activation screen, reached by clicking the one-time link in the "Your Partner Central account is ready" email. The user is unauthenticated. They set a password here to complete account setup, then are logged in and redirected to onboarding-welcome.html.

Flow context

  • Entry: partner-set-password.html?token=eyJ... — the one-time token from the account-ready email
  • This page: Unauthenticated, pre-activation. Token validated server-side on load; if invalid or expired, show an error and offer to re-request.
  • On submit: POST token + new password to /auth/activate; session issued; token marked as used; redirect to onboarding-welcome.html
  • Subsequent logins: partner-login.html with the password they just created

Password requirements

  • Minimum 12 characters
  • One uppercase letter
  • One number
  • One special character
  • Requirements tick green in real-time as the user types
  • Submit button disabled until all requirements met and passwords match

Technical Details

  • Token validation: GET /auth/validate-token?token=... on page load — if invalid, replace card with expired-link state
  • Activation endpoint: POST /auth/activate — body: {token, password}; returns session cookie + redirect URL
  • Email field: Pre-filled from token payload (JWT sub claim), readonly — user cannot change it here
  • After activation: Partner_Central_User__c.Account_Status__c → 'Active', First_Login__c = null (triggers welcome flow detection)
