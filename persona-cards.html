Design Specs

Summary

User persona reference documenting 8 key roles (partner admins, reps, agents, and Equinix staff) with mapped access permissions, portal visibility, and team management responsibilities to guide product design and access control configuration.

Jobs to Be Done

  • Map each persona to Salesforce Profile + Permission Set combinations for access control
  • Show portal access differences between partner types (Reseller, Distributor, TSD, Agent)
  • Document partner admin vs. rep vs. internal role capabilities and responsibilities
  • Illustrate team management flows (PM adds reps, TSD manages agents, Distributor manages sub-resellers)
  • Identify missing screens based on persona access needs and workflows
  • Enable access control configuration and permission set assignment in Salesforce backend

Design Specification

Primary Content

  • 8 detailed persona cards covering partner-side users and Equinix-internal roles
  • Each persona includes: avatar, name, role, partner type, goals, pain points
  • Partner Admin personas with team management responsibilities and organization-wide visibility
  • Sales rep personas focused on deal registration, training completion, and commission tracking
  • Persona relationship map showing organizational hierarchy and inter-portal interactions
  • Access control mapping matrix: Profile + Permission Set combinations governing portal visibility and feature access

Interactive Elements

  • Two-column persona grid with card layout and visual hierarchy
  • Persona headers with avatars, names, and role titles
  • Access badges showing portal features with semantic coloring (green=allowed, gray=restricted)
  • Goal and pain point lists with semantic icons for visual scanning
  • Access matrix data grid showing Profile/Permission Set combinations
  • Relationship diagram with arrows showing persona hierarchies and portal interaction flows

Functionality

  • Reference Documentation & Design Specification
    • Non-interactive reference page providing documentation-only specification input describing 8 key user personas with role definitions, responsibilities, and portal access requirements
    • Persona profiles including Avatar, Name, Title, and Tier eligibility (Gold/Silver/Bronze) for access control mapping guidance
    • Cross-functional alignment enabler documenting user types and permission model relationships across Partner roles and Equinix internal teams
  • Access Control Rule Development
    • Permission mapping guidance serving as specification input for Profile and PermissionSet creation in Salesforce org: PCP_Partner_Rep, PCP_PM_Admin, PCP_Distributor, PCP_TSD, PCP_PSM_Full, PCP_Program_Admin
    • Access matrix documentation showing Feature vs. Persona permissions grid guiding OrgWideDefault and Sharing Rule configuration for Account-based visibility
    • Role hierarchy reference showing reporting lines and portal access delegation ensuring proper cascading permissions from PCP_Program_Admin down to PCP_Partner_Rep
  • Wireframe Design Alignment
    • Persona access path representation ensuring all portal pages show correct conditional content based on user Profile and PermissionSet membership verified against persona definitions
    • Design guidance documentation for layout variations per persona (Partner Dashboard shows order summary, PSM Dashboard shows all account orders, Agent view shows only assigned cases)
    • Feature visibility matrix documenting which pages and components render for each persona preventing development of inaccessible features

Technical Details

Key Objects & Access Model

  • User (Profile = PCP_Partner_Rep, PCP_PM_Admin, PCP_Agent_Base, PCP_PSM_Full, PCP_Program_Admin)
  • PermissionSet (PCP_Partner_Base, PCP_PM_Admin, PCP_Distributor, PCP_TSD, PCP_PSM_Full, PCP_Program_Admin)
  • Partner__c — Linked to User for org-scope access control via Account Hierarchy
