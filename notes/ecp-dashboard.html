Design Specs

Summary

Central dashboard providing customers with unified visibility across infrastructure, orders, support cases, and contract status with quick access to common operational workflows.

Jobs to Be Done

  • Display real-time service inventory across multiple metros
  • Track pending orders and provisioning progress
  • Monitor support case resolution and SLA compliance
  • Review contract terms and upcoming renewal dates
  • Quick access to common operational workflows

Design Specification

Primary Content

  • Welcome banner with customer name and contract details
  • KPI cards: Active Cabinets, Cross-Connects
  • Active Deployments by Metro table with power utilization and status
  • Recent Orders table with order status and expected delivery dates
  • Open Support Cases table with priority and SLA status
  • Service Health status indicators for each data center
  • Contract Summary table with renewal dates and account team

Interactive Elements

  • Click case/order numbers to view details
  • Quick action tiles: Order Services, Request Cross-Connect
  • Health card indicators showing operational/maintenance status per metro
  • Sortable table columns and expandable detail rows

Functionality

  • Data Integration & Real-Time Sync
    • Account-scoped dashboards pulling real-time asset inventory from DCIM via scheduled API callout every 5 minutes storing latest inventory counts in custom Dashboard_Cache__c object
    • Order status automation synced from fulfillment system through MuleSoft middleware integration parsing fulfillment queue status into Order.Status picklist values
    • Power consumption tracking updating Asset.Power_Draw_W__c field from DCIM sensors via inbound middleware API call from DCIM system
  • SLA & Escalation Management
    • SLA tracking and escalation alerts tied to case age and priority displayed on dashboard via dynamic formula fields calculating hours open per case
    • Milestone breach warning logic on Case EntitlementProcess triggering visual alert component when expected resolution time minus current time is less than 24 hours
    • Critical case routing via Process Builder triggering VF page redirect to escalation workflow when Case.Priority = 'Critical'
  • Account Health & Value Metrics
    • Utilization calculations showing cabinet capacity percentage and power draw percentage against contracted limits using aggregate SOQL queries on Asset totals
    • Contract renewal reminders via automated email workflow firing 90 days before Contract.End_Date__c expiration using time-based workflow action
    • Health status indicators per metro syncing from maintenance calendar with color coding (Green=Operational, Yellow=Maintenance, Red=Incident)
  • Workflow Automation & Navigation
    • Quick-launch buttons routing to preset create/view workflows with URL parameters pre-populated from Account context (e.g., ?AccountId={!Account.Id})
    • New Order quick action form pre-filling customer account lookup triggering case creation in same transaction via Process Builder

Design Context: Customer vs. Partner Visibility

The Equinix Customer Portal (ECP) is fundamentally separate from the Partner Channel Program. Customers like Acme Corporation see their operational infrastructure, service configurations, and support status in real-time. Partners (e.g., Stark Industries) see only aggregated deal status and high-level health metrics. Detailed service configurations, case contents, and billing data remain private to the customer and Equinix account team.

Sarah Mitchell appears as the Equinix Account Executive in both portals because she bridges the co-sell relationship—she sells to Stark Industries (partner) and supports Acme Corporation (customer), but her visibility differs in each portal.

Architectural Decision: Network Utilization & Value Realization

Question: Should customers see network throughput and utilization metrics at an aggregate level to understand if they're getting value for their money?

Decision: Yes — this is a primary concern, but framed as value realization rather than real-time NOC monitoring. Customers have their own tools (SNMP, internal NOC) for packet-level diagnostics. What the portal should surface is utilization relative to spend: Am I using 90% of my cross-connects? Are cabinets near capacity? Is power draw close to contracted limits? This "Am I getting my money's worth?" lens justifies renewals and drives expansion conversations.

Implementation: The ECP Interconnection & Fabric page (currently placeholder) should include: port utilization % per cross-connect, traffic volume trends (30/60/90 day), active vs. provisioned cross-connect ratios, and a "value score" comparing spend to utilization. Power/space utilization already exists on the Services & Orders page. Network utilization completes the picture.

Data Source: Equinix SmartView / DCIM telemetry feeds → Salesforce via integration middleware. Port utilization from Equinix Fabric API. Refresh cadence: hourly for utilization, daily for trend aggregations.

Architectural Decision: AI-Powered Spend Optimization (Phase 2)

Question: Should there be AI tools for optimizing customer spend based on patterns in usage?

Decision: Yes — flagged as Phase 2 feature. The telemetry data required (cross-connect utilization, power draw trends, cabinet occupancy patterns) won't exist at PCP launch because it depends on DCIM/SmartView integration that ships separately. However, the concept is compelling for portal stickiness and upsell.

Concept — "Smart Insights" Widget: An Agentforce-powered (or external ML) recommendations card on the ECP Dashboard that surfaces actionable cost optimizations. Examples: "Save $3,200/mo by consolidating 3 underutilized cross-connects from 10G to 1G ports" or "Based on DC5 growth trend, you'll need additional cabinet capacity in ~4 months — pre-configured quote available." Could also flag waste patterns: "4 cross-connects in SV5 running at 12% utilization — review for decommission."

Prerequisite: Requires minimum 6 months of telemetry history for pattern detection. ML model needs training data across multiple customers (anonymized) to establish baseline utilization norms by service type and metro. Consider Salesforce Agentforce Analytics or external model served via Heroku/AWS endpoint.

UX Placement: Dashboard card between KPIs and Deployments sections. Show 2-3 top recommendations with estimated savings. Link to full "Optimization Report" page (future build). Include "Dismiss" and "Remind me later" actions per recommendation.
