Why this screen is different from pm-home-dashboard

  • No deals, MDF, or tier points: ISVs don't register deals or accumulate tier spend credits. Their program progression is driven by integrations live, API health, and marketplace quality.
  • API health is a first-class metric: Resellers never look at API call volume. For an ISV, uptime and latency are their SLA to Equinix and their customers. The mini-chart and three-stat row replace the pipeline table a reseller would see.
  • Co-sell, not deal registration: ISVs co-sell alongside Equinix AEs — they're surfacing their tech as part of a bundle. The motion is "here are joint opportunities," not "I'm registering a deal I sourced." The isv-co-sell.html stub represents this distinct flow.
  • Marketplace listing completeness: ISVs' partner value is partly determined by how discoverable and compelling their marketplace entry is. A completeness bar with specific missing items (case study, demo video) drives action better than a static status label.
  • Certification as a recurring deadline: ISV integrations have annual or semi-annual recertification requirements tied to API version support. The warning KPI card (38 days to renewal) and the sidebar cert link make this visible before it's a crisis.

ISV tier model (simplified)

  • Enrolled ISV: Onboarded, sandbox access, 0–1 live integrations
  • Validated ISV: 2+ live integrations, marketplace published, API uptime ≥99.9% (NovaSpark is here)
  • Premier ISV: Validated + Featured listing + $1M co-sell pipeline. Unlocks Innovation Partner Fund (co-marketing budget) and dedicated TAM hours

This tier model is derived from Equinix's public ISV program description at equinix.com/partners/isv and analogous ISV partner programs at AWS and Azure (both publicly documented).

Stub screens introduced

  • isv-integrations.html — integration detail + API test results
  • isv-marketplace.html — listing editor (completeness, media uploads)
  • isv-co-sell.html — co-sell pipeline view (TAM-managed opps)
  • isv-support.html — developer support tickets, sandbox access
  • isv-resources.html — API docs, changelogs, certification paths

Differentiation from reseller (pm-) screens

The ISV surface deliberately omits: deal registration, MDF requests, lead management, tiered discount structure, and QBR scheduling. These are reseller constructs. In their place: API health monitoring, integration staging pipeline (dev → QA → live), marketplace listing management, and co-sell pipeline visibility.

Accessibility notes

  • Bar chart has individual title attributes per bar for screen reader context. A proper implementation would use an accessible SVG or table with aria-label.
  • Activity feed uses role="log" and aria-live="polite" for updates.
  • Locked GTM item is conveyed semantically via text ("🔒 Locked") not just opacity alone.
  • Role badge is #0369a1 (distinct from reseller red, referral teal, exec purple, CMM amber) — ISV blue signals a technical/build persona vs sales persona.
