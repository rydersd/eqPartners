Design Specs

Summary

Partner application form collecting company profile, capabilities, and service expertise to assess eligibility and route applications to appropriate review teams via Reseller or lightweight Lead Referral pathways.

Jobs to Be Done

  • Collect partner company and contact information
  • Assess partner capability through revenue, employee, and service expertise
  • Determine partner tier eligibility based on form answers
  • Route application to appropriate Equinix team for review
  • Support both full Reseller and lightweight Lead Referral pathways

Design Specification

Primary Content

  • Sidebar program information: benefits, links to partner guides
  • Partner Type dropdown selector for Reseller vs. Lead Referral
  • Your Information form section: name, email, phone
  • Company Information section: company name, website, location
  • Reseller-specific fields: revenue history, employee counts by function, mix percentages
  • Cloud services and provider expertise multi-select lists
  • Third-party DC provider and channel partnership selections
  • Industry vertical markets where they have customer presence

Interactive Elements

  • Partner Type dropdown toggles form sections between Reseller and Lead Referral
  • Multi-select listboxes for cloud services, providers with keyboard navigation hints
  • Business mix percentage fields with real-time total calculation validation
  • reCAPTCHA verification checkbox before submission
  • Submit and Clear buttons for form control

Functionality

  • Form Behavior & Conditional Logic
    • Client-side conditional field visibility based on Partner Type selection via JavaScript change event listener on partner-type dropdown toggling .conditional-label and .form-card[data-partner-type] visibility using CSS display property
    • Form reset functionality triggered by Clear button calling form.reset() and clearing all localStorage keys with prefix 'onboarding_apply_'
    • Auto-save to browser localStorage executing on input change events persisting field values to key 'onboarding_apply_{fieldName}' for recovery on page reload
  • Data Validation
    • Real-time mix percentage total validation executing on input change events summing Product_Sales%, Service_Sales%, and Consulting_Services% fields and updating .mix-total display
    • Validation styling changing .mix-total.valid (green) or .mix-total.invalid (red) based on whether sum equals 100% or not
    • Server-side form validation enforcing required fields per partner type via Apex controller method validating Partner_Application__c required fields and generating validation error messages for UI display
  • Security & Bot Prevention
    • reCAPTCHA v2 integration for bot prevention using Google reCAPTCHA client library automatically validating on form submission and passing g-recaptcha-response token to server
    • Server-side reCAPTCHA token verification calling Google reCAPTCHA verification endpoint (/api/verify-recaptcha) before form submission acceptance
    • Token validation requiring response.success == true and response.score > 0.5 threshold before allowing form processing
  • Record Creation & Routing
    • Automated Partner_Application__c record creation with routing rules via Apex trigger after form submission parsing form data and creating single Partner_Application__c record with Status = 'Submitted'
    • Application_Answer__c junction records creation looping through multi-select field values (cloud services, providers, vertical markets) and creating child Application_Answer__c records per selection
    • Auto-tier calculation formula field on Partner_Application__c evaluating revenue, employee count, and service offerings against tier thresholds assigning Tier_Recommendation__c ('Gold', 'Silver', 'Bronze')
  • Notifications & Handoff
    • Email notification to Channel Team via Process Builder workflow when Partner_Application__c.Status__c = 'Submitted' calling Messaging.sendEmail() to Channel_Manager_Queue__c
    • Email template merging application data fields including company name, contact email, revenue summary, and tier recommendation into email body
    • Assignment rule routing Partner_Application__c to appropriate review queue based on tier using Assignment Rules with tier picklist value as routing condition

Technical Details

Key Objects

  • Partner_Application__c — Main record capturing form data with Status = 'Submitted'
  • Application_Answer__c — Junction table storing multi-select values (cloud services, providers, verticals)
  • Partner__c — Account record created on application acceptance
