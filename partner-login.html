Design Specs

Summary

Login screen for Partner Central. Three states: default email/password, one-time link (arrived from onboarding email), and error. First-time users arriving from the account-ready email land directly in the one-time link state — no password entry required for initial login.

States

  • Default: Standard email + password form with SSO option. Existing users returning to the portal.
  • One-time link: User clicked the magic link from their onboarding email. Page detects the ?token= param, shows a confirm-and-log-in screen. No password needed. On confirm, token is redeemed and a standard session is issued.
  • Error: Bad credentials or expired one-time link. Inline error banner above the form. Link to password reset or support.

First-Login Flow

  • User clicks link in account-ready email → partner-login.html?token=eyJ...
  • Page detects token param, shows OTL confirm state
  • User clicks "Confirm and log in" → token redeemed, session issued, token marked as used
  • Redirect to onboarding-welcome.html (first-login flag detected)
  • Subsequent logins: standard email/password or SSO

SSO

  • Email domain lookup: if user enters email matching a known SSO domain, offer SSO button as primary action
  • Button label updates to show provider name once domain is identified (e.g. "Continue with Okta")
  • For mixed orgs without SSO, email + password remains primary

Technical Details

  • Auth method: Salesforce Experience Cloud login page (custom-branded) or headless auth via Connected App
  • OTL token: JWT, single-use, 72-hour TTL, stored as Auth_Token__c on Partner_Central_User__c; redeemed via POST /auth/redeem-token
  • SSO: SAML 2.0 or OIDC via Salesforce Identity; domain routing table stored in SSO_Domain__c object
  • Remember me: Extends session cookie from default 8 hours to 30 days
  • Failed attempts: Rate limit after 5 failed attempts; CAPTCHA on attempt 6+; lockout after 10
