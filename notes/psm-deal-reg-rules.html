Important: Changes made to these rules will affect all new deal registrations submitted after the change time. Existing deals retain their original rules under the policy version in effect when registered. Use caution when modifying conflict detection and approval thresholds.

Automatically detects when multiple partners claim the same geographic territory or customer segment. Flags overlapping registrations for conflict resolution.

Incumbency & Deal Type Priority Rules
Existing Customer Expansion Priority
When existing customer has established vendor relationship, extension/expansion deals receive priority protection. Protects incumbents from poaching during expansion opportunities.
Active
Renewal Deal Fast Track
Expedites approval process for customer renewals and contract extensions. Renewal deals bypass standard approval workflow and auto-approve if registered by incumbent partner.

New Logo vs Expansion Deal Rules
Enabled
Different protection and approval rules apply based on deal type. New logo (first-time customer) and expansion (existing customer, new use case) get standard protection. Renewals and support contracts get fast-track approval.

Configuration Guidelines

Protection Period: Recommended 90 days for standard enterprise deals. Extend to 120 days for high-value infrastructure projects (>$500K). Consider competitive landscape when setting this value.

Auto-Approval Thresholds: Set based on partner tier performance and deal risk profile. Gold partners with strong compliance history can have higher thresholds. Review quarterly and adjust based on deal velocity and approval cycle metrics.

Conflict Detection: Adjust customer match threshold based on false positive rates. Start at 85% and monitor for optimization. Territory overlap detection should remain enabled to prevent channel conflict.

Incumbency Rules: These protect long-standing partner relationships while allowing healthy competition. Fast-track renewals to reduce sales cycle time. Expansion deals should generally follow standard approval process.

Design Specs

Summary

Deal registration rule configuration interface for PSMs to centrally manage protection periods, auto-approval thresholds, conflict detection, and incumbency rules across all partners. Includes audit trail and impact warnings.

Jobs to Be Done

  • Configure protection period and deal approval thresholds centrally for all partners
  • Enable/disable conflict detection and territory overlap scanning
  • Set incumbency rules to balance protection with healthy competition
  • Track all configuration changes with audit trail for compliance
  • Export rules for documentation and disaster recovery

Design Specification

Primary Content

  • Impact warning banner explaining rule change effects on pending registrations
  • Protection Period Configuration card with days input, explanation, and default/range guidance
  • Auto-Approval Thresholds card with tier-based amounts (Gold, Silver, Bronze) and enabled toggles
  • Conflict Detection section with Territory Overlap toggle and Customer Match threshold %
  • Incumbency Rules section with Existing Customer Expansion and Renewal Fast Track toggles
  • Audit Trail table showing recent configuration changes with date, user, and details
  • Configuration Guidelines card with best practices for each setting category

Interactive Elements

  • Numeric input fields for Protection Period days and tier-based approval thresholds
  • Percentage input field for Customer Match detection threshold
  • Toggle switches for Territory Overlap, Partner Exclusivity, Renewal Fast Track
  • Save Changes button to persist configuration
  • Reset to Defaults button to revert to system baseline
  • Export Rules button to download configuration as PDF/CSV
  • View Change History link to expand audit trail details

Functionality

  • Rule Configuration Retrieval & Display
    • Query Deal_Registration_Rule__c custom setting records and display current values on form
    • Load protection periods, approval thresholds, and customer match settings for editing
    • Display configuration guidelines alongside input fields for best practice reference
  • Configuration Updates & Validation
    • Update field values via form inputs and commit changes via API with validation
    • Enforce Protection Period must be between 30-180 days with default 90 days
    • Validate Auto-Approval thresholds are positive (typical Gold $50K, Silver $25K, Bronze $10K)
    • Verify Customer Match threshold is between 0-100% with typical value 85%
  • Impact Assessment & Change Tracking
    • Display impact notification showing # of pending DealReg__c records affected by rule changes
    • Create Rule_Change_Log__c audit record for each configuration change with Before/After values
    • Auto-invalidate cached rule evaluations when configuration changes detected
    • Count pending DealReg__c records via SOQL before persisting changes for impact visibility
  • Reporting & Audit Trail
    • Retrieve Audit Trail from Rule_Change_Log__c sorted by CreatedDate DESC for change history
    • Support Export Rules by rendering configuration as formatted PDF document
    • Maintain immutable audit trail with field history tracking enabled for compliance

Technical Details

Validation & Business Logic

  • Protection Period must be between 30-180 days; default 90
  • Auto-Approval thresholds must be positive; typical Gold $50K, Silver $25K, Bronze $10K
  • Customer Match threshold must be 0-100%; typical 85%
  • Rule changes require PSM profile; non-reversible without audit trail
  • Warning banner counts pending DealReg__c records via SOQL before persisting changes
  • Audit trail immutable once created; field history tracking enabled for compliance
