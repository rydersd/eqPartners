Trigger Condition

Sent when a partner application record changes status to Approved in Salesforce. Triggered by PSM action or automated review rule.

  • From address: no-reply@partner.equinix.com
  • Reply-to: assigned PSM's Equinix address
  • CTA link: one-time tokenized URL (7-day expiry)

Design Notes

The 3-step "what happens next" section sets expectations so users aren't surprised by the MFA setup screen. Naming it "secure access" rather than "MFA" reduces abandonment from users unfamiliar with authenticator apps.

Program tier shown as "pending onboarding" — confirmed after onboarding wizard completes.

Accessibility

  • CTA button contrast ratio meets WCAG AA
  • All decorative color elements (badge, dots) have text labels
  • Plain-text fallback version required for production
  • Link expiry stated in text, not just visual badge

Summary

HTML email wireframe for the system-generated acceptance notification. Sent when a partner application is approved. Primary function: deliver a tokenized setup link and set expectations for the authentication and onboarding steps ahead.

Flow Position

Registration chain: Apply → Confirmation → [PSM reviews] → Acceptance Email (this) → Auth Setup → Onboarding Wizard

Jobs to Be Done

  • Confirm application approval — remove anxiety about status
  • Deliver the one-time setup link securely
  • Set expectations: 3 steps, ~3 min auth setup, ~10 min onboarding
  • Introduce the assigned PSM before the first call
  • Avoid overwhelming — this email should be short and action-focused

Design Specification

Primary Content

  • Email subject: "You're in — Welcome to Equinix Partner Central"
  • Approval badge (green) — positive reinforcement above the fold
  • Application summary box: org name, partner type, tier, PSM name
  • 3-step "what happens next" with numbered steps
  • Primary CTA: "Set Up Your Account →" links to tokenized auth setup URL
  • Link expiry stated (7 days with explicit date)
  • PSM contact for pre-onboarding questions

Interactive Elements

  • CTA button — primary action, links to onboarding-auth-setup.html
  • PSM mailto link
  • Footer links: Unsubscribe, Privacy, Terms

Functionality

  • Tokenized URL: one-time use, 7-day TTL, scoped to applicant email + application record
  • Token validates against Salesforce application record on auth setup page load
  • Expired tokens: redirect to "link expired" page with option to request new link
  • Email triggered by Salesforce Flow when Application_Status__c = 'Approved'
  • Reply-to routed to PSM, not a no-reply address

Design Notes

  • Email client frame is a wireframe device — shows From/To/Subject metadata for spec clarity, not part of the actual email HTML
  • Dummy data: Steve Rogers (CloudBridge Technologies Inc.), PSM Marcus Chen — consistent with project personas
  • Copy avoids "MFA" or "two-factor" terminology at this stage; introduce gently on the auth setup page itself
  • Program tier shown as "pending" — only confirmed after onboarding wizard completion to avoid over-promising
  • Plain-text version required in production; wireframe covers HTML version only
