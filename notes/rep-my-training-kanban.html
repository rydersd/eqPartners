Design Specs

Summary

Kanban-based training progress dashboard enabling reps to visualize course status across workflow columns (Not Started, In Progress, Completed, Expired) with drag-and-drop status management, progress tracking, and prerequisite enforcement.

Jobs to Be Done

  • Visualize training status in workflow format
  • Manage course progression across status categories
  • Prioritize courses by moving in kanban
  • See course distribution across categories
  • Track courses through completion lifecycle
  • Filter to focus on relevant courses

Design Specification

Primary Content

  • Training progress KPI header with required (4/8), elective (1/3), and overall (50%) completion metrics
  • Kanban board with four columns: Not Started (5 cards), In Progress (1 card), Completed (4 cards), Expired (1 card)
  • Course cards per column displaying title, course type badges (Technical/Business), enrollment category badges (Required/Elective), duration, due date, completion score (for Completed column), prerequisite notes (where applicable)
  • Filter bar with "Show: All/Required/Elective" options and course search box
  • View toggle links to switch between Table, Card, and Kanban views (with Kanban as active)
  • Recommended Next Steps section with 3 priority action cards (Resume, Re-enroll, Start)

Interactive Elements

  • Drag cards between kanban columns to update course status
  • Click Start/Resume/Re-enroll/View Certificate action links on cards
  • Toggle between Table/Card/Kanban views via view links
  • Filter course display by "All/Required/Elective" options
  • Search courses by title or keyword in search box
  • Collapse/expand kanban columns to manage screen real estate

Functionality

  • Kanban Column Mapping & Population
    • Partner_Training__c.Status__c mapped to 4-column kanban layout: 'Not Started' (new enrollments), 'In Progress' (started but not completed), 'Completed' (finished with Completion_Score__c), 'Expired' (Expiration_Date__c < TODAY() or cert validity period exceeded)
    • Columns populated via SOQL queries filtered by Status__c and Contact=logged-in user, sorted by Due_Date__c ASC (most urgent first); real-time updates via Platform Events on Partner_Training__c record changes
    • Training cards display: Course Name, Due Date, Status badge, Progress bar (for In Progress), and action buttons (Start, Resume, Re-enroll, View Certificate)
  • Progress Metrics & KPIs
    • Overall progress percentage calculated as: (Completed count / (Required count + Elective count)) × 100; populated from Partner_Training__c records grouped by Status__c='Completed'
    • Required vs. Elective breakdown fetched from Partner_Training__c.Is_Required__c flag; compared against Tier_Course_Requirement__mdt[Account.Partner_Tier__c] to determine KPI target (e.g., "8/10 Required")
    • Progress KPI displayed at top of page; details modal shows breakdown by category and completion dates
  • Prerequisite Enforcement & Validation
    • Prerequisite validation on card load: IF Course.Prerequisite_Course__r exists AND Prerequisite_Training__c WHERE Contact=logged-in user AND Status__c != 'Completed' THEN disable Start button and display "Prerequisite: [Course Name]" note on card
    • Start Course button enabled only when all prerequisites are met; clicking launches LMS SSO redirect with Partner_Training__c.__c and Course.SumTotal_Course_ID__c
  • Drag-and-Drop & Status Updates
    • Drag-and-drop functionality moves cards between kanban columns; on drop, updates Partner_Training__c.Status__c via Apex DML handler
    • Column counts and progress KPI recalculated in real-time after status update; updates reflected immediately in UI
    • Overdue course detection: IF Partner_Training__c.Due_Date__c < TODAY() THEN show red/urgent styling on card; prevents course start unless admin override applied
  • Expiration & Re-enrollment Logic
    • Auto-expiration logic: nightly Training_Expiration_Monitor scheduled flow queries Certification__c WHERE Expiration_Date__c < TODAY(); updates linked Partner_Training__c.Status__c='Expired' and sends notification email to Contact
    • Re-enroll button creates new Partner_Training__c enrollment with Status='Not Started', Due_Date__c=TODAY()+365 days; original Certification__c retained for audit trail
    • Expired certifications moved to Expired column; old cert visible in collapsed details section
  • Filtering, Search & Recommended Next Steps
    • Filter buttons (All/Required/Elective) apply WHERE clause filter: Partner_Training__c.Is_Required__c=[true|false|all]; kanban refreshes with filtered results
    • Search box filters by keyword: SOQL WHERE Course.Name LIKE '%[keyword]%' OR Course.Description__c LIKE '%[keyword]%'; results update in real-time client-side
    • Recommended Next Steps section populated from highest-priority Partner_Training__c: In Progress courses with lowest completion %, Expired certs blocking prerequisites, and next required course in learning path

Technical Details

Salesforce Objects & Automation

  • Partner_Training__c: Status__c (Not Started, In Progress, Completed, Expired), Due_Date__c, Completion_Date__c, Completion_Score__c, LMS_Module_Index__c, Is_Required__c, Course__c lookup, Contact lookup
  • Course__c: Name, Duration__c, Is_Required__c, Category__c, Difficulty__c, Prerequisite_Course__r (parent lookup), Valid_Months__c (for auto-expiration calculation)
  • Certification__c: Status__c, Issue_Date__c, Expiration_Date__c, Partner_Training__c lookup, Verification_Code__c
  • Tier_Course_Requirement__mdt: Partner_Tier__c, Required_Course_Count__c, Elective_Course_Count__c (defines KPI targets per tier)
  • Nightly scheduled flow: Training_Expiration_Monitor flow queries Certification__c with Expiration_Date__c < TODAY(), updates linked Partner_Training__c to Status='Expired', and sends notification to Contact
  • Kanban column population via Visualforce or LWC component making SOQL queries at page load and on drag-drop completion, subscribing to Partner_Training__c record change events for real-time updates
  • Prerequisite validation enforced in Course__c validation rules and frontend logic before allowing course start action
